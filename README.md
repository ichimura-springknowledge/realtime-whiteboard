# realtime-whiteboard

社内 LAN で複数人が同時に使える、ログイン不要のホワイトボード。

- `client/` — React + **TypeScript** + Vite（Canvas 描画 / perfect-freehand）
- `server/` — **Python** + FastAPI + python-socketio（リアルタイム配信・永続化）

描いた内容はサーバーのディスクに保存されるので、**全員がブラウザを閉じても、
サーバーを再起動しても消えません**。

## 社内で使う（本番構成）

社内に 1 台、常時起動しておく PC でサーバーを動かします。クライアントも
サーバーが配信するので、**使うポートは 1 つだけ**です。

```bash
# 1) 一度だけ: 依存関係の取得とクライアントのビルド
cd server
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
cd ../client && npm install && npm run build && cd ..

# 2) サーバーを起動（ポートと、許可するサブネットを指定）
cd server
PORT=5000 ALLOWED_CIDRS=192.168.1.0/24 .venv/Scripts/python run.py
```

Windows の PowerShell では:

```powershell
cd server
$env:PORT = "5000"
$env:ALLOWED_CIDRS = "192.168.1.0/24"
.venv\Scripts\python run.py
```

あとは各自のブラウザで、サーバー機の IP を開くだけです。

```
http://192.168.1.201:5000/?room=team-a
```

`?room=` を省略するとルーム ID が自動生成され、URL に書き戻されます。その URL を
共有すれば同じボードに入れます（ツールバーの「招待リンク」でコピーできます）。

> HTTPS ではないため `navigator.clipboard` は使えません。コピーは選択方式
> （`document.execCommand`）で行っています。それも失敗した場合は URL を
> ダイアログで表示するので、手でコピーしてください。

サーバー機の IP は起動時のログに表示されます。IP が変わると URL も変わるので、
ルーターで固定 IP を割り当てておくと安定します。

> **ポート番号は、ファイアウォールで受信が許可されているものを選びます。**
> Windows は既定で外部からの接続を遮断するため、許可されていないポートを使うと
> 同僚からは一切つながりません。許可済みのポートは以下で確認できます（管理者権限は不要）。
>
> ```powershell
> Get-NetFirewallRule -Direction Inbound -Enabled True -Action Allow |
>   Where-Object { ($_ | Get-NetFirewallApplicationFilter).Program -eq 'Any' } |
>   ForEach-Object { "{0} : {1}" -f $_.DisplayName, ($_ | Get-NetFirewallPortFilter).LocalPort }
> ```
>
> 空なら、管理者権限のある人に受信許可を追加してもらう必要があります（後述）。

### アクセス範囲の制限について

`ALLOWED_CIDRS` で指定した範囲**以外からの接続は 403 で拒否**します（HTTP も
WebSocket も）。未設定の場合はプライベートアドレス全体とループバックを許可します。
複数指定はカンマ区切り、単一ホストは `/32`、IPv6 の CIDR もそのまま書けます。

```bash
ALLOWED_CIDRS=192.168.1.0/24,192.168.2.0/24   # 2 つのサブネット
ALLOWED_CIDRS=192.168.1.50/32                 # 1 台だけ
```

> **これは認証ではありません。** 同じ Wi-Fi につながれば誰でも（来客用 Wi-Fi が
> 同じサブネットならその利用者も）閲覧・編集できます。ルーム ID を知らなければ
> そのボードには入れませんが、ID は秘密情報として扱えるものではありません。
> 社外の人に見せたくない情報の置き場所としては使わないでください。
> 人単位で制限したい場合はログイン機能の追加が必要です。

判定にはソケットの接続元アドレスを使い、`X-Forwarded-For` などのヘッダは
信用しません（詐称できるため）。リバースプロキシの背後に置く場合はこの前提が
崩れるので、プロキシ側で制限してください。

### つながらないとき

サーバー起動時のログに、共有すべき URL が表示されます。まずそこを確認してください。

**1. Windows ファイアウォールの受信許可（最初にこれを疑う）**

Windows は既定で外部からの接続を遮断します。とくに Wi-Fi が「パブリック
ネットワーク」に分類されていると、ポートを開けない限り同僚からは一切つながりません。

まず、**既に許可されているポートが無いか**を確認してください（上記のコマンド）。
あればそのポートを `PORT` に指定するだけで済みます。

無い場合は、**管理者として実行した PowerShell** で一度だけ設定します
（管理者権限が無いアカウントでは実行できないため、情報システム担当に依頼してください）。

```powershell
New-NetFirewallRule -DisplayName "Realtime Whiteboard" -Direction Inbound `
  -Protocol TCP -LocalPort 5000 -Action Allow -Profile Any -RemoteAddress LocalSubnet
```

**2. 切り分け** — 同僚のブラウザで `http://<サーバー機の IP>:<ポート>/health` を開きます。

| 症状 | 原因 |
|---|---|
| ページが開けない / タイムアウト | ファイアウォール、または Wi-Fi のプライバシーセパレータ（下記） |
| JSON が表示される | ネットワークは通っている。URL のポート番号やルーム ID を確認 |
| 403「社内ネットワーク内からのみ…」 | `ALLOWED_CIDRS` の範囲外。サーバーのログに拒否した IP が出ます |

**3. Wi-Fi のプライバシーセパレータ / AP アイソレーション**

アクセスポイントの機能で、同じ Wi-Fi につながった端末同士の通信を遮断する設定です。
来客用 Wi-Fi では既定で有効なことが多く、有効だと**どうやってもつながりません**。
ファイアウォールを開けても駄目な場合はこれを疑い、ネットワーク管理者に確認するか、
サーバー機を有線 LAN につないでください。

**4. その他**

- サーバー機と同僚が別のサブネット（例: 社員用と来客用で分かれている）にいないか
- 起動ログに出ている IP と、共有した URL の IP が一致しているか
- スリープでサーバー機が落ちていないか（電源設定でスリープを無効にしておく）

### 保存について

- 保存先: `server/data/boards.json`（`DATA_FILE` 環境変数で変更可）
- 一時ファイル + 置換で原子的に書くため、書き込み途中で落ちても壊れたファイルは
  残りません
- 描き終わった線・文字・取り消しは**即座に**書き込みます。しばらく操作が無かった
  あとの変更は待ち時間ゼロ、連続した操作は 0.1 秒にまとめます。サーバーが強制終了
  されても、直前に描いたものは残ります（実測で確認）
- ドラッグ中の位置更新だけは 1 秒間隔にまとめます。毎秒数十回届くうえ、失っても
  困らないためです
- 読めない状態のファイルは `boards.broken-<時刻>` に退避し、空で起動します
- バックアップはこの JSON を控えておけば十分です
- ルームあたり 3000 要素を超えると古いものから消えます
- 「全消去」した内容は復元できません

## 開発時の起動

ターミナルを 2 つ開いて、それぞれで実行します。

```bash
cd server && .venv/Scripts/python run.py     # http://localhost:5000
cd client && npm run dev                     # http://localhost:5173（LAN にも公開されます）
```

開発時のクライアントは、**ページを開いたホスト名の :5000** に自動で接続します
（`VITE_SERVER_PORT` で変更可）。`http://192.168.1.201:5173/` を他の PC から開いても
そのままつながります。接続先を完全に固定したい場合だけ `client/.env` に
`VITE_SERVER_URL` を設定してください（`client/.env.example` を参照）。

ビルド版はサーバー自身が配信するため、**ポート番号によらず同じオリジン**に接続します。
`PORT` を変えてもクライアントの再ビルドは不要です。

## 使える機能

| ツール | 操作 |
|---|---|
| ペン | ドラッグで描画。色と太さを変更できます |
| 消しゴム | ドラッグでなぞった部分を消します（誰が描いた線でも消えます） |
| 文字 | クリックした位置に入力欄が出ます。Enter で確定、Esc で取り消し |
| 文字・画像の移動 | 文字ツールのまま、置いた文字や画像をドラッグすると好きな位置へ動かせます（カーソルが ✥ に変わります） |
| 画像の貼り付け | `Ctrl+V` でクリップボードの画像を貼り付け。画像ファイルのドラッグ＆ドロップも可 |
| テキストの貼り付け | `Ctrl+V` でクリップボードの文字列を貼り付け |
| □ / ○ / ↗ | 四角・丸・矢印。ドラッグで大きさを決めます |
| 戻る / やり直す | `Ctrl+Z` / `Ctrl+Shift+Z`。**自分が行った操作**（追加・移動）だけを 1 つずつ取り消します |
| 全消去 | ルーム全員の描画をすべて消します |
| PNG / SVG | 今の盤面をファイルに書き出します |

戻る操作が自分の分だけを対象にするのは、共同編集中に他の人の描いたものが
勝手に消えないようにするためです。

参加者のマウス位置は色分けして表示されます。色はサーバーが接続順に割り当てるので、
誰かが他人の色を名乗ることはできません。盤外に出たときと切断時に消え、保存はしません。

### 画像の貼り付けについて

スクリーンショットを撮って `Ctrl+V`、あるいは画像ファイルをボードにドラッグ＆
ドロップすると貼り付きます。対応形式は **PNG / JPEG / GIF / WebP**、1 枚 8 MB まで。

- 貼り付けた画像は**ボードのファイルには入りません**。`server/data/images/` に
  別ファイルとして保存し、ボードは**そのパスだけ**を持ちます。スクリーンショットは
  数百 KB あり、ボードのファイルは入室のたびに全員へ送られるためです
- ファイル名は**内容のハッシュ**です。同じ画像を何度貼っても実体は 1 つで、URL は
  永久にキャッシュして構いません
- 大きすぎる画像は送る前に長辺 1600px へ縮小します。数千ピクセルの写真をそのまま
  送ると、同じ部屋の全員を待たせることになるためです
- 受け取ったデータは**ヘッダではなく先頭バイトで形式を判定**します。`image/png` を
  名乗る HTML などは保存しません
- どのボードからも参照されなくなった画像は、**サーバー起動時に削除**します

> **ボードの内容をクリップボードへコピーする（`Ctrl+C` で画像として）ことはできません。**
> `navigator.clipboard.write()` は HTTPS でしか使えないためです。PNG / SVG の
> 書き出しを使ってください。貼り付け（`Ctrl+V`）は平文 HTTP でも動きます。

### 書き出しについて

- **PNG** — 見たままの画像。表示サイズの 2 倍の解像度で、背景は白です
- **SVG** — 拡大しても劣化しない形式。あとから Illustrator などで編集できます。
  貼り付けた画像は data URL として埋め込むので、このサーバーに繋がらない場所でも開けます

消しゴムは canvas の `destination-out`（下の描画を削る）で実現していますが、SVG に
同じ機能はありません。そこで書き出し時は、**消しゴムより前に描かれたものだけを
マスクでくり抜いたグループに包み**、消しゴムより後のものはその外に置きます。
画面上の見た目と同じ結果になります。

書き出されるのは**今ブラウザに表示されている範囲**です。ウィンドウの大きさで
書き出しサイズが変わります。

## 通信イベント

| イベント | 方向 | 内容 |
|---|---|---|
| `board:init` | server → client | 入室時にルームの描画履歴を配信 |
| `room:peers` | server → client | ルームの参加人数 |
| `stroke:start` | client → server → client | 描き始め（線の色・太さ・始点） |
| `stroke:points` | client → server → client | 描画中の点を逐次追加（フレームごと） |
| `stroke:end` | client → server | 描き終わり。`item:add` として配信される |
| `stroke:cancel` | server → client | 描画途中で切断した参加者の線を破棄 |
| `item:add` | 双方向 | 確定した要素（線 / 文字）を履歴に追加 |
| `item:move` | 双方向 | 文字・画像の位置を更新（ドラッグ中もフレームごとに配信） |
| `item:remove` | 双方向 | 要素を 1 つ取り消す（戻る操作） |
| `shape:preview` | 双方向 | 図形をドラッグ中の形（毎フレーム、図形ごと送る） |
| `board:clear` | 双方向 | ルームの全消去 |
| `cursor:move` | 双方向 | 参加者のマウス位置。保存しない |
| `cursor:leave` | 双方向 | 盤外に出た / 切断した参加者のカーソルを消す |

型は `client/src/types.ts` の `ServerToClientEvents` / `ClientToServerEvents` で
定義しており、イベント名と引数の取り違えはコンパイル時に検出されます。

履歴は「線」と「文字」を同じ 1 本の配列（`items`）として順番どおりに保持します。
消しゴムは `erase: true` の線として同じ配列に入り、描画時に
`globalCompositeOperation = 'destination-out'` で下の描画を削ります。
これにより、消しゴム自体も「戻る」で取り消せます。

「戻る」は自分の操作を並べたアクション列（`{type: 'add'}` / `{type: 'move'}`）を
さかのぼる方式なので、文字の移動も 1 手として取り消せます。

クライアントから届くペイロードは、サーバー側 `app/items.py` で**既知のフィールドだけを
使って組み立て直してから**ルームに入ります。型・範囲・長さが合わないものは捨てるか
既定値に丸めるので、壊れた入力でサーバーが落ちることはありません。

座標は小数第 2 位に丸めます。ポインタが返す生の値は 1 つ 18 文字ほどになり、その
コストを点の数だけ、通信と保存の両方で払うことになるためです。0.01px の差は画面に
出ません（同条件で保存サイズが 42% 減りました）。

## 描画の仕組み

確定済みの要素はオフスクリーンの canvas に一度だけ焼き付け、毎フレームはそれを
転送したうえに「まだ描いている途中のもの」だけを重ねます。要素が増えただけのときは
増えた分だけを追記し、undo・移動・全消去のときだけ作り直します。ドラッグ中の要素は
キャッシュから外して毎フレーム描き直す側に回すので、移動しても盤面全体の再構築は
起きません。

毎フレーム全ストロークの輪郭を計算し直すと、1600 要素の盤面で 1 フレーム 33ms
(30fps) まで落ちていました。現在は 3000 要素（ルーム上限）でも 16.7ms を保ちます。

## サーバーの構成

| ファイル | 役割 |
|---|---|
| `app/main.py` | Socket.IO のイベント処理、FastAPI の health と静的配信、アクセス制限 |
| `app/access.py` | 接続元アドレスの判定（`ipaddress` による CIDR マッチ） |
| `app/items.py` | 受信ペイロードのサニタイズ、ルーム ID の正規化 |
| `app/images.py` | 貼り付けられた画像の保管・配信・掃除 |
| `app/board.py` | ルームの状態（要素の並び、描画中の線） |
| `app/store.py` | ディスクへの保存と復元（デバウンス + 原子的な書き込み） |

カーソル位置だけは保存も集約もせず、受け取ったその場で同じルームの他の参加者へ
中継するだけです。

| 変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `5000` | 待ち受けポート（ファイアウォールで許可されたものを選ぶ） |
